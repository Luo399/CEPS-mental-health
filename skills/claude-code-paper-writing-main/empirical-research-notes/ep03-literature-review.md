## 一、什么是 Skill

**Skill 是一个可复用的能力包。**

我们用一个具体场景来理解它的必要性。

设当前研究主题是「耐心资本对企业 ESG 表现的影响」。**没有 Skill 时**，让 Claude Code 完成这一主题的文献综述至少需要四步显式指令：

| 步骤 | 指令 | Claude Code 的动作 | 常见问题 |
|------|------|---------------------|----------|
| 1 | 帮我搜索"耐心资本"相关文献 | 调用网络搜索工具 | 拿回的多是零散信息，质量不高 |
| 2 | 改用 OpenAlex 重新检索 | 通过 OpenAlex API 拿到结构化学术元数据 | OK |
| 3 | 把这批文献的 PDF 下载到本地 | 解析 DOI 与开放获取链接，逐篇下载 | 部分文献无开放获取，需手工补 |
| 4 | 按 GB/T 7714 整理到 `references.bib` | 生成符合中文国标的 BibTeX 条目 | OK |

如果明天换成「数字经济」、后天换成「供应链韧性」，这四步又要重复一遍。**主题在变，流程不变**——这就是 Skill 应当登场的位置。

Skill 的两个核心用处：

1. **流程固化、一次声明多次复用。** 把"检索 → 下载 → 整理"这一串动作打包成一个 Skill，研究主题切换时只换关键词，流程本身不再重写。

2. **给 Claude 不擅长的事配上脚本。** 比如修改 Word、修改 Excel，原生交互在 Claude Code 里并不顺手。Skill 内部可以预置一段写好的脚本，Claude 调用 Skill 时实际执行的是这段脚本——把"语言模型不擅长操作"的环节交给"代码擅长操作"的部分。

## 二、Skill 怎么装

虽然 Skill 是 Claude Code 原生支持的能力，但要查找别人写好的 Skill，最高效的办法是先装一个 Skill：`find-skills`。它的职责就是帮你查找、定位、安装其它 Skill。

### 2.1 安装 find-skills

操作流程：

1. 浏览器搜索 `skills.sh`，进入官网首页
2. 找到下载量最高的那一项 `find-skills`（写本期讲义时累计下载量是 140 多万）
3. 复制它给的安装命令
4. 打开 IDE 的终端（Windows 与 macOS 上都在 IDE 顶部菜单里"新建终端"）
5. 把命令粘贴回车

安装过程中会被问到两个选项：

- **装在哪个 Agent 下** —— 直接回车，Claude Code 会自动选
- **作用范围（Scope）** —— 通用类的 Skill（比如 find-skills 本身），建议选 `global`。否则每开一个新项目都要重装一次，得不偿失。

最后命令行会让你确认 `proceed`，确认即安装完成。

### 2.2 用 find-skills 找其它 Skill

装完之后，可以直接在 Claude Code 里这样说：

```
请你帮我用 find-skills 这个 skill 去查找有没有制作 skill 比较好的 skill。
```

它会调用 find-skills 内部的检索流程，命中 Anthropic 官方维护的 `skill-creator`。装上 skill-creator 之后，你就能告诉 Claude Code "我要把这一套流程做成一个 Skill"，由它生成符合规范的 Skill 文件。

> **小结**：第一次进入 Skill 生态，建议先把 `find-skills` 和 `skill-creator` 这两个安装到 global。前者用来查找，后者用来制作。

## 三、当前最顺手的两个文献综述 Skill

文献综述方向我用过的 Skill 不止两个，目前体感最稳的是下面这两个。

### 3.1 systematic-literature-review

工作方式：

1. 给一个研究主题（关键词），例如"耐心资本"
2. Skill 内部把关键词喂给 OpenAlex API
3. OpenAlex 返回 100 多篇候选英文文献
4. Skill 对返回的每一篇做相关性打分，1–10 分排序
5. 把高分那一批返回给你

它的特点是 **全量评分**——不只是返回前 N 篇，而是先评所有候选，再筛选。这一点对相关性敏感的研究比较友好，避免 OpenAlex 默认排序把高引但不切题的文献排在前面。

### 3.2 ReviewGen 套件

作者是 Harry Lee，仓库在 GitHub 上叫 `harrylee0412/review-gen`。它不是单一 Skill，而是一个套件，里面包含 4 个 Skill。

**安装方式**：直接把 GitHub 仓库链接发给 Claude Code，让它装就行：

```
请你帮我安装这个 skill：https://github.com/harrylee0412/review-gen
```

它和 systematic-literature-review 同样基于 OpenAlex 检索，差别在两点：

- **挑期刊更严**——倾向返回 ABS、AJG 体系内的好刊
- **多了一条平替路径**——可以走 Perplexity 接口，绕到网上抓部分中文 paper 的 PDF

如果研究方向偏管理学、组织行为，ReviewGen 在英文期刊覆盖上会更对你的胃口。

### 3.3 共同的硬伤：中文文献覆盖弱

两个 Skill 都基于 OpenAlex，而 OpenAlex 上的中文期刊本身就少。中文文献的主流来源是知网，但**知网不对外开放 API**——这是目前所有文献综述类 Skill 的共同瓶颈，没有完美的解。

ReviewGen 的 Perplexity 平替路径能拿到一部分中文 paper 的 PDF，但元数据不完整：标题、原文有，参考文献的引用结构常常缺失。要做一份完整的中文文献综述，最后这一步还是得你自己回知网补。

**实务建议**：

- 英文文献综述部分 → 全部交给 Skill 跑
- 中文文献综述部分 → Skill 走一遍拿到部分 PDF，**剩下的用知网手工检索 + Claude Code 协助提取关键信息**

## 四、文献到手以后

文献检索 + 下载只是文献综述的第一段。后面还有两件事可以让 Claude Code 接着做。

### 4.1 整理参考文献条目

让 Claude Code 把已下载文献按 GB/T 7714 格式整理到 `references.bib`：

- 中文条目用 `gbt7714` 包对应字段
- 英文条目用标准 BibTeX 字段

整理好以后写论文时直接 `\cite{key}` 就能用。这一步也可以让两个 Skill 自带的导出脚本完成，但有时候它们在引用编号细节上会出错，整理后人工核一遍 key 与 entry 的对应关系。

### 4.2 提取变量定义（可选）

以"耐心资本"为例。这一个概念在不同论文里有好几种代理变量：

- 换手率
- 银行偿债期限
- 机构投资者持股久期
- 股东大会投票久期

每篇论文用的是哪一种代理、为什么这样选、对应的计量公式是什么——这些信息散在不同文章的"变量定义与计算"那一节，散在不同位置不同表述里。

让 Claude Code 把这些信息从全部文献里集中提取出来，存成一份变量表。表里至少包含：

| 字段 | 内容 |
|------|------|
| 变量名 | 例如：耐心资本 |
| 代理变量 / 计算方式 | 例如：机构投资者持股久期均值 |
| 公式 | 例如：$Patient_{i,t} = \frac{1}{N}\sum_{j=1}^{N} Holding\_Duration_{i,j,t}$ |
| 数据来源 | 例如：CSMAR / Wind |
| 出处 | 例如：作者 (年份) "标题" 期刊 |

**这一份表，会在两个场景下被反复调用：**

1. **设计自己的变量** —— 看清楚同行都怎么定义、各自的边界与争议在哪，再做选择
2. **稳健性检验** —— 替代变量做 robustness 时，从这张表里直接挑就行，不需要每次回到原文翻

把这份表存在项目目录下，正文章节起草阶段，Claude Code 就能拿它做上下文，不会出现"自己写论文写到一半发现变量定义和文献不一致"的尴尬。

### 4.3 阅读笔记的存放位置

我习惯直接在 IDE 本地读 PDF，不再切到外部工具。读完每篇之后把心得、提取出来的关键信息都码在同一个项目目录下。两个原因：

- **上下文集中**：写正文章节调用 Claude Code 起草时，它会一并读取这些笔记
- **避免割裂**：不同工具间转抄是科研工作流里最容易出错的环节之一

笔记文件名建议带文献的 BibTeX key，方便和 `references.bib` 对应。

## 五、本期小结

文献综述这一步的标准动作：

1. 装 `find-skills` 和 `skill-creator`（global scope）
2. 用 `systematic-literature-review` 或 ReviewGen 做英文文献检索 + 评分 + 下载
3. 中文文献仍走知网手工检索，必要时让 Claude Code 协助提取关键信息
4. 让 Claude Code 整理参考文献、提取变量定义到统一的变量表
5. 在项目本地读 PDF，笔记和提取信息存进同一个目录

完成这五步，你手上就具备了：

- 一批已筛选、已下载、已格式化引用的文献
- 一份覆盖核心变量的变量定义表
- 一份本地化的阅读笔记

这就是后续写正文章节时 Claude Code 能调用的素材底座。

## 附：关键术语

- **Skill** —— Claude Code 的可复用能力包，可包含提示词、脚本和元信息
- **OpenAlex** —— 开放学术元数据数据库，通过 API 提供论文、作者、机构、引用关系等信息
- **GB/T 7714** —— 中国国家标准的参考文献著录格式
- **代理变量（Proxy Variable）** —— 用一个可观测变量近似一个不可直接观测的概念
- **稳健性检验（Robustness Check）** —— 通过替换变量定义、改变样本范围等方式验证主回归结果是否稳定
